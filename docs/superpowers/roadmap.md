# Stem Examspace roadmap (from the owner's specification)

Master plan: `docs/owner/2026-11-functional-specification.pdf` (owner decision 2026-11-17). Everything is built for the web first (owner decision 2026-11-18). Each part goes design, then plan, then careful build (a fresh builder per step, an independent reviewer after each step, a whole-branch review at the end). Nothing reaches the live site without the owner's go-ahead.

| Part | Specification | What it delivers | Status |
|---|---|---|---|
| Phase 1A | §8–10 | Home or centre sitting, one or more centres per exam, question paper upload, personalised papers with QR codes, timed release, print packs, scan check | Building |
| Phase 1B | §2–5, §7 | Year groups 8 to 13; registration statuses with rejected registrations kept and a reason; corrections that keep the original; staff permissions per action and the coordinator role; importing existing students; exam series; booking reference and receipt; clash warnings | Next |
| Phase 1C | §3 | Public pages (about, subjects, fees, exam formats, booking instructions, contact, policies) that staff edit without a developer; versioned policies; the remaining pages restyled in the new look | Next |
| Phase 2 | §11–16 | Home sitting screen (countdown, rules, parent acknowledgement), scanning pages with the phone's camera in the browser, script upload with receipt, centre attendance to collection with custody, bulk scan splitting by QR, exception queue, the script repository | Later |
| Phase 3 | §17–21 | Web marking like RedMarker on any device including iPad with Pencil, mark schemes and rubrics, allocation by question or script, double marking and moderation | Later |
| Phase 4 | §22–25 | Results calculation and publication, student progress and analysis, parent dashboard, admin dashboards and reports | Later |
| Phase 5 | §26 | AI help with clear limits; offline marking and native apps if still wanted | Later |
